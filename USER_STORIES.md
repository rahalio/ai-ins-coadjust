# Coadjust — User stories

**Product:** [PRODUCT.md](./PRODUCT.md)


### Claims handler

- As a claims handler, I want the model's recommendation, its confidence, and the two or three factors driving it presented inside my existing claim view, so that I can agree or disagree on the merits rather than guessing what the system saw.
- As a claims handler, I want to record why I am overriding a recommendation in one interaction, so that my disagreement improves the model instead of disappearing into a free-text note.
- As a claims handler, I want to see how my paired decisions performed against final settled outcomes, so that I can calibrate my own scepticism rather than defaulting to acceptance.
- As a claims handler whose queue is being automated, I want to see the destination role, the skills gap, and the training start date, so that I can plan rather than wait for a restructuring announcement.

### Claims team leader

- As a team leader, I want to see which decision types in my team are paired, automated, or human-only and why, so that I can explain the operating model to my team with evidence.
- As a team leader, I want an alert when a handler's acceptance rate of model recommendations diverges from the model's demonstrated accuracy, so that I can address over-deference before it shows up as leakage.
- As a team leader, I want to reallocate capacity between queues when volume shifts, so that automating glass claims does not leave bodily-injury referrals ageing past their service target.

### Claims quality and conduct manager

- As a quality manager, I want the combination premium reported per decision type against model-only and human-only baselines, so that I can challenge an automation proposal that would reduce accuracy for a cost saving.
- As a conduct manager, I want any declinature, indemnity reduction, or fraud referral to carry the name of the accountable human and the policy version in force, so that I can answer an ombudsman referral without reconstructing the file.
- As a conduct manager, I want vulnerable-customer and bodily-injury claims to be structurally excluded from automated allocation, so that our fair-treatment obligations are enforced by the system and not by handler discretion.
- As a quality manager, I want an automation change to be suspended automatically when cycle time or complaint rate deteriorates on that decision type, so that we detect harm in-period rather than in the annual review.

### Workforce planning and capability lead

- As a workforce planner, I want to see the capacity released by each automation change and the queues it can be redeployed into, so that headcount planning is driven by the actual pairing design.
- As a capability lead, I want readiness measured per paired role from production decision quality, so that I can report progress against the one-in-four readiness baseline in terms an executive will accept.
- As a capability lead, I want the cost of each reskilling path reported against the capacity it releases and fills, so that I can make the case for increasing a reskilling budget that is currently flat.

### Chief AI Officer and governance

- As the Chief AI Officer, I want a single register of every claims decision type, its current allocation mode, its evidence, and its approval, so that scaling AI across claims is governed centrally rather than negotiated team by team.
- As a governance committee member, I want allocation policy changes to require named approval and to be reproducible for any historic claim, so that our automation decisions are defensible years later.
- As a data protection officer, I want handler decision data segregated from performance management use with an auditable access policy, so that we can consult works councils honestly about what the system does and does not do.
